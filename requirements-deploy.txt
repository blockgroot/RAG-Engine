# Production/deploy dependency set — used ONLY by the Dockerfile.
#
# This is `requirements.txt` minus `sentence-transformers` (which drags in
# torch, multi-GB and unused once EMBEDDING_BACKEND=remote /
# RERANKER_BACKEND=remote point at a hosted provider — see app/embeddings/
# local.py and app/reranker/local.py, both of which `import sentence_transformers`
# lazily *inside* their constructor, gated behind backend=="local"). Dropping it
# from the deploy image keeps the build small and fast without touching any
# runtime code path.
#
# `transformers` is kept (unlike sentence-transformers) because
# app/ingestion/chunk_tokens.py imports `AutoTokenizer` unconditionally at
# module load — token-aware chunking runs regardless of embedding backend.
# It needs no torch/tensorflow/flax backend: AutoTokenizer only loads
# tokenizer config/vocab files, verified by actually building and booting this
# image (`docker build . && docker run ...`) rather than assumed.
#
# If you ever deploy with EMBEDDING_BACKEND=local or RETRIEVAL_RERANK_ENABLED
# pointed at the local CrossEncoder, install `sentence-transformers>=3.0.0`
# back into the image (or just build from requirements.txt instead of this
# file) — the app raises a clear ImportError rather than silently degrading.
#
# Keep this in sync with requirements.txt (same versions) whenever a
# non-local-model dependency changes — same discipline CLAUDE.md already
# documents for requirements.txt vs pyproject.toml.
