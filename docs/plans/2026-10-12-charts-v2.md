## 1. Goal and what "done" means

A member can ask for a chart of **anything we index or can read live** and gets
a chart that is **true to the source** or a **plain statement that the data is
not there**. Never a chart of something else.

Covered surfaces: web chat (Chart mode), uploaded files in a chat, indexed
documents of every connector (tables, sheets, PDFs, prose), connector activity
(GitHub, Linear, Slack, Notion, Drive), a live read when nothing is stored, and
Slack mentions/DMs (chart posted as an image in the thread).

### Success criteria (measured by the eval in Phase 0, gated per phase)

| Metric | Target |
|---|---|
| **Wrong-data charts** (a chart drawn from data that does not answer the question) | **0** on the golden set |
| Correct chart when the data exists (right source, right measures, right period) | ≥ 90% |
| Correct "not available" when the data does not exist | ≥ 95% |
| Same question × 5 runs → identical spec | 100% |
| Chart-mode latency, stored data, p95 | ≤ 6 s |
| Chart-mode latency, on-demand extraction or live read, p95 | ≤ 25 s, with progress events |
| Slack chart reply (image in thread), p95 | ≤ 30 s |

## 2. What is broken today (root causes, traced)

The production symptoms were: a "Total Count by Metric — 2026 H1 Operational
Metrics" chart (billing categories, total 150) for a question about quarterly
revenue/opex/profit FY 2025–26; Notion credited when the user expected Drive;
stacked/dual-axis requests refused; different outcomes per run.

Production data on 2026-10-12 (aggregate counts only):
- documents: none-provider (uploads/other) 24, Slack 22, Drive 19, Notion 16,
  Linear 12.
- **Only 7 of 19 Drive documents have ever been checked for tables**
  (`tables_checked_at`), so most Drive files can never be charted yet.
- doc_tables: 10 Notion + 7 Drive + 6 other `table` origin; 4 Notion `text`
  origin. Prose extraction **is** on in production (13 queue rows, all `done`
  after one attempt). No Drive document has prose-extracted figures.

### Root causes (confirmed in code)

| # | Cause | Where |
|---|---|---|
| R1 | Every visible table (up to 6) is offered to the classifier. Ranking orders, never removes. A scope with a few tables offers all of them, related or not. | `app/insights/tables.py::rank`, `app/agent/routing.py::_document_tables` |
| R2 | The prompt pushes tables for money questions: "Prefer a table when they ask about figures IN a document (sales, budget, **revenue**…)". | `app/insights/resolve.py::_prompt` |
| R3 | A table pick is validated for **structure only** (handle offered, columns exist, types fit). Nothing checks that the picked column is the measure asked for. No "data not available" outcome exists once a pick validates. | `app/insights/tables.py::parse_pick`, `resolve._parse_intent` |
| R4 | A spec carries **one** value column. "Revenue, opex and profit" cannot be expressed; two measures are silently dropped. | `resolve.ChartSpec.value` |
| R5 | Tables cannot be stacked (`stacked_bar` never allowed for a table); there is no dual axis anywhere (backend, prompt, `Chart.tsx`). A wide table (`Quarter | Starter | Pro | Enterprise`) has no "Plan" column to split by → refusal. | `tables.parse_pick`, `frontend/components/Chart.tsx` |
| R6 | The asker's time range is dropped for tables (`_note_range` returns early on `table_id`). "Q1 FY26" is a category, not a period. Fiscal years do not exist. | `resolve._note_range` |
| R7 | The refusal lists "Document tables I can use" = all offered tables, so a refusal looks like it ignored relevant data. | `resolve._refusal` |
| R8 | Non-determinism: no `temperature` on any call (provider default ≈ 1.0); `LLM_MODEL=auto` and the per-user picker can change the model; classifier `MAX_TOKENS = 200` is tight for a ~17-field JSON reply (truncation → refusal); a 429 → "Couldn't build this chart". The offered table set also changes between runs (backfill, background extraction, live fetch saves tables mid-query). | `app/llm/openai_provider.py::generate`, `resolve.MAX_TOKENS`, `routing._chart_mode_route` |
| R9 | Prose extraction check is not semantic: a number cell passes if it equals **any** number in the quote; labels match by substring ("Pro" ⊂ "Profit"); **column headers and units are never checked**. "Q1 revenue was ₹12L, Q2 grew to ₹15L" accepts `["Q2","₹12L"]`. | `app/doctables/text_adapter.py::_cell_in_quote`, `verify_rows` |
| R10 | Queue states are lossy: an unparseable or truncated model reply returns `[]` and is marked `done` (no retry, no record); an empty result keeps old tables; `_finish` has no claim check (a re-enqueue during processing is overwritten to `done`); an FK error after a re-ingest aborts the whole batch. The chart path never reads the queue, so "still being read" looks like "no data". | `app/doctables/queue.py` |
| R11 | `tables_checked_at` is stamped even when an adapter was disabled, so turning prose extraction on later never reaches already-indexed documents. Backfill is 20 docs/sync. | `app/ingestion/pipeline.py::_store_tables`, `backfill_tables` |
| R12 | Drive PDFs become flat text (pypdf), so their tables are lost; Drive `.xlsx` is unsupported; Sheets read the first tab only. (Uploads already read PDF/XLSX tables via pdfplumber/openpyxl.) | `app/sources/google_drive.py::fetch_document` |
| R13 | No duplicate handling across connectors: identical content in Notion and Drive is two documents with separate tables; whichever has a stored table wins. Attribution itself is correct (it names the document holding the chosen table). | — |
| R14 | Slack posts chart **numbers as text**; there is no image. The bot has no `files:write` scope. | `app/api/slack_events.py::_with_chart_values`, `app/config/settings.py` (Slack scopes) |
| R15 | `Chart.tsx` is a 1,277-line hand-rolled SVG renderer: one unit and one y-axis; a category × split chart becomes a value-sorted leaderboard ("Q1 · Pro"), losing order; no zoom, legend toggling, export or data-table view. | `frontend/components/Chart.tsx` |

## 3. Target architecture

```
                         ┌──────────────── INGEST / BACKGROUND ────────────────┐
 Connectors / uploads ──►│ Dataset adapters (doctables)                         │
                         │  • TableAdapter   (sheets, csv, xlsx, pdf, docx, md) │
                         │  • TextAdapter v2 (figures in prose → FACTS, verified)│
                         │  adapter_runs state machine (per doc × origin × hash) │
                         │  profile v2: types, units/row, PERIODS (fiscal),     │
                         │              wide/long shape, content hash           │
                         │  table card chunk → embedded (retrievable, ACL'd)    │
                         └───────────────────────────────────────────────────────┘
 Activity facts (unchanged store, same grammar)
                                         │
 Question (web Chart mode / Slack) ──────▼───────────────────────────────────────
  1. Candidates   : hybrid retrieval over table cards + activity metrics,
                    viewer predicate in SQL, RELEVANCE FLOOR (offer nothing if
                    nothing is relevant), dedup by content hash
  2. Resolve      : model (temperature 0, JSON) returns
                    requested_measures[] (quoted) + bindings + shape + period
  3. Verify       : code checks every quote, every binding (measure ↔ column
                    similarity), units, periods, shape-vs-data. Partial →
                    chart what is bound + name what is missing. None → step 4.
  4. Fallback     : (a) on-demand extraction of the top relevant docs not yet
                    read → back to 1;  (b) live read of the named/top doc →
                    extract → store → back to 1;  (c) "not available" naming
                    what was searched. NEVER a different metric.
  5. Aggregate    : SQL over stored rows (multi-measure, period ranges)
  6. Payload v2   : data + encoding + provenance + caveats (snapshot)
                    │                         │
           web: ECharts renderer       Slack: chartrender (PNG) → files upload v2
```

## 4. Decisions

- **D1 — Keep the invariant.** Numbers come only from SQL over stored rows; the
  model selects and quotes, code verifies. (Every production analytics product
  that promises correct numbers does this: ThoughtSpot, Cube, Cortex, Genie
  trusted assets; see the 2026-09-30 plan §3.)
- **D2 — Multi-measure specs.** A spec carries 1–4 measures. Each measure is
  bound to one number column (or one activity metric) and carries the asker's
  quoted words for it. This one change unlocks "revenue, opex and profit",
  stacked plans, and dual axis (two units).
- **D3 — Coverage check is the anti-hallucination gate.** Each requested
  measure must be bound by evidence: its quote is in the question **and** the
  bound column/metric is semantically close to the quote (embedding similarity
  of short strings, using the existing embedder) **or** a format-level token
  match on the header. No word lists. Unbound measure → named as missing.
  Zero bound → no chart.
- **D4 — Relevance floor on candidates.** Offering nothing is correct when
  nothing is relevant. A named document/table is always offered.
- **D5 — Periods are data.** Profiling parses period labels ("Q1 FY26",
  "H1 2026", "FY 2025–26", "Apr-25", dates) into `period_start/period_end/grain`
  using the org's fiscal-year start. Time ranges and time axes work on tables.
- **D6 — Prose figures become FACTS with one-figure clauses.** Each fact =
  measure, series, period, value, unit, and the minimal clause it came from.
  The clause must hold exactly one value number. That one rule removes
  mis-association.
- **D7 — Explicit extraction state machine** (`doc_adapter_runs`) replacing
  `tables_checked_at` + `doc_text_queue.status`. The chart path reads it and can
  run extraction **on demand** for a relevant unread document.
- **D8 — Live fallback** reuses `app/livetools` readers and the same adapters;
  what a live read finds is stored, so the next ask is fast.
- **D9 — Determinism.** temperature 0, JSON response format where supported,
  enough tokens, one pinned chart model per org, and a **spec cache** keyed on
  question + candidate set + data versions + model. Numbers are recomputed each
  time; only the interpretation is cached.
- **D10 — Frontend: Apache ECharts** (Apache-2.0, SVG renderer, tree-shakable,
  built-in stacked/dual-axis/dataZoom/aria/decal, SSR-capable). Wrapped in one
  thin React component; no wrapper library. Pin an exact version ≥ 6.0.0 at
  implementation time (6.0 is released;
  https://echarts.apache.org/handbook/en/basics/release-note/v6-feature).
  - Rejected: Recharts (no real dual axis ergonomics, weaker large-data
    performance); Plotly (≈3 MB bundle); Vega-Lite (good grammar, weaker
    interactive polish, a second spec language); keeping `Chart.tsx` (R15).
- **D11 — Slack images rendered server-side in Python** from the same payload
  v2, new package `app/chartrender/` (`base.py`, `matplotlib_renderer.py`,
  `factory.py`). Matplotlib (Agg, lazily imported) is offline, deterministic,
  and needs no browser or Node in the API image (self-hosted goal). The
  palette is mirrored from `frontend/components/chartColors.ts` and a test
  keeps them equal.
  - Alternative kept on file: ECharts SSR (`renderToSVGString`) in Node +
    resvg for pixel parity. Rejected for now: it adds a Node service to the
    API path.
- **D12 — Upload to Slack via `files.getUploadURLExternal` +
  `files.completeUploadExternal`.** `files.upload` was sunset on 2025-11-12
  (https://docs.slack.dev/changelog/2024-04-a-better-way-to-upload-files-is-here-to-stay,
  https://docs.slack.dev/reference/methods/files.completeUploadExternal).
  Needs the `files:write` bot scope.
- **D13 — Duplicates.** Tables get a `content_hash`. Identical tables visible
  to the viewer are offered once; the source the asker named wins, else the most
  recently modified. The chart says "Same table also in: …".

## 5. Data model changes (`app/db/schema.sql`)

Rules: every `ALTER TABLE … ADD COLUMN` goes right after that table's
`CREATE TABLE`; tenant tables carry `org_id`; a one-time data fix goes behind a
`schema_marks` row; apply with `apply_schema()`.

```sql
-- Profile v2 on tables
ALTER TABLE doc_tables ADD COLUMN IF NOT EXISTS content_hash TEXT;
ALTER TABLE doc_tables ADD COLUMN IF NOT EXISTS shape TEXT NOT NULL DEFAULT 'long'; -- long | wide
ALTER TABLE doc_tables ADD COLUMN IF NOT EXISTS period_key TEXT;      -- column key holding periods, if any
ALTER TABLE doc_tables ADD COLUMN IF NOT EXISTS extracted_at TIMESTAMPTZ NOT NULL DEFAULT now();
CREATE INDEX IF NOT EXISTS idx_doc_tables_hash ON doc_tables (org_id, content_hash);

-- Per-row parsed period and per-cell units (units: {"c3": "₹", "c4": "%"})
ALTER TABLE doc_table_rows ADD COLUMN IF NOT EXISTS period_start DATE;
ALTER TABLE doc_table_rows ADD COLUMN IF NOT EXISTS period_end DATE;
ALTER TABLE doc_table_rows ADD COLUMN IF NOT EXISTS period_grain TEXT;  -- day|week|month|quarter|half|year
ALTER TABLE doc_table_rows ADD COLUMN IF NOT EXISTS units JSONB NOT NULL DEFAULT '{}';
-- text-origin rows: the clause, and the surrounding context the labels came from
ALTER TABLE doc_table_rows ADD COLUMN IF NOT EXISTS context TEXT;

-- Extraction state machine (replaces doc_text_queue.status + tables_checked_at)
CREATE TABLE IF NOT EXISTS doc_adapter_runs (
    document_id   UUID REFERENCES documents (id) ON DELETE CASCADE,
    attachment_id UUID REFERENCES conversation_attachments (id) ON DELETE CASCADE,
    org_id        UUID NOT NULL REFERENCES organizations (id) ON DELETE CASCADE,
    workspace_id  UUID REFERENCES workspaces (id) ON DELETE CASCADE,
    origin        TEXT NOT NULL,                 -- table | text
    content_hash  TEXT NOT NULL,                 -- of the text the adapter read
    status        TEXT NOT NULL,                 -- pending|running|done|empty|partial|failed|skipped
    attempts      INT NOT NULL DEFAULT 0,
    claim_token   UUID,
    claimed_at    TIMESTAMPTZ,
    error         TEXT,                          -- short reason, never document text
    tables_written INT NOT NULL DEFAULT 0,
    text          TEXT,                          -- bounded copy while pending; NULL after
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    CHECK ((document_id IS NULL) <> (attachment_id IS NULL))
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_adapter_runs_doc ON doc_adapter_runs (document_id, origin) WHERE document_id IS NOT NULL;
CREATE UNIQUE INDEX IF NOT EXISTS uq_adapter_runs_att ON doc_adapter_runs (attachment_id, origin) WHERE attachment_id IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_adapter_runs_pending ON doc_adapter_runs (updated_at) WHERE status = 'pending';

-- Org fiscal year (1 = January, 4 = April). Display + period parsing only.
ALTER TABLE organizations ADD COLUMN IF NOT EXISTS fiscal_year_start_month SMALLINT NOT NULL DEFAULT 1;

-- Spec cache: the INTERPRETATION of a question, never numbers.
CREATE TABLE IF NOT EXISTS chart_spec_cache (
    org_id        UUID NOT NULL REFERENCES organizations (id) ON DELETE CASCADE,
    workspace_id  UUID REFERENCES workspaces (id) ON DELETE CASCADE,
    key           TEXT NOT NULL,   -- sha256(question_norm, candidate ids+versions, model, prompt version)
    spec          JSONB NOT NULL,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_chart_spec_cache ON chart_spec_cache (org_id, key);

-- Debug traces (ids and scores only; no document text, no answer text)
CREATE TABLE IF NOT EXISTS chart_traces (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    org_id        UUID NOT NULL REFERENCES organizations (id) ON DELETE CASCADE,
    workspace_id  UUID REFERENCES workspaces (id) ON DELETE CASCADE,
    surface       TEXT NOT NULL,          -- web | slack | api
    model         TEXT,
    candidates    JSONB NOT NULL,         -- [{kind, id, score, offered}]
    reply_raw     TEXT,                   -- model reply, capped 4 KB
    decision      JSONB NOT NULL,         -- outcome, bindings, coverage, fallback steps
    latency_ms    INT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

Migration of existing state (behind a `schema_marks` row): copy
`doc_text_queue` rows to `doc_adapter_runs` (`done` → `done`; others →
`pending`), create a `pending` run for every document with `tables_checked_at
IS NULL`, then keep `doc_text_queue` read-only for one release and drop it in
the next. Existing `doc_tables` rows get `content_hash` and profile v2 on the
next run (Phase 2 re-profile job, bounded per tick).

Purge: `chart_traces` older than 14 days and `chart_spec_cache` older than 24 h
are removed on the external tick. Any successful ingest clears that org's
`chart_spec_cache` (same rule as `query_answer_cache`).

## 6. Phases

Each phase: **flag**, **files**, **tasks**, **tests**, **exit gate**.
Flags live in a new `ChartsSettings` dataclass in `app/config/settings.py`

### Phase 0 — Eval harness and tracing (do first; nothing user-visible)

**Why:** every later phase is gated on numbers, and today a wrong chart leaves
no trace of why it was chosen.

Files: `evaluation/charts_eval.py` (new), `tests/fixtures/charts/` (new),
`app/insights/trace.py` (new), `app/agent/routing.py`.

Tasks
1. **Golden set** `tests/fixtures/charts/golden.jsonl` — at least 80 cases, each
   `{fixture, question, expect}` where `expect` is `{kind: chart|not_available|
   text_question, source_doc?, measures?: [...], group?, split?, period_range?,
   shape?}`. Must include:
   - the four production questions verbatim (quarterly revenue/opex/profit FY
     2025–26; stacked revenue by Starter/Pro/Enterprise per quarter; dual axis
     active customers vs churn rate; the "Total Count by Metric" trap where only
     an unrelated metrics table exists → `not_available`);
   - wide and long tables, prose-only figures, a PDF in Drive, an XLSX, a
     multi-tab Sheet, a Notion inline database, an upload of each type;
   - the same table in Notion and Drive (dedup + named source);
   - activity questions per connector (must not regress);
   - mixed units, fiscal years (April start), half-years, missing quarters;
   - adversarial: injected instructions in a table cell or document text.
2. **Fixtures** are synthetic documents loaded into staging under a dedicated
   eval org (never production data).
3. **Runner** `python -m evaluation.charts_eval --runs 5` prints the §1 metrics
   per case, with a determinism column (5 runs → identical spec?).
4. **Tracing**: `trace.record(...)` writes one `chart_traces` row per Chart-mode
   request (candidates with scores, raw reply capped, decision, latency). Never
   raises. Log the trace id in the API log line.

Tests: `tests/test_charts_trace.py` (row written, capped, no document text,
org-scoped).
Exit gate: baseline numbers for today's code recorded in
`docs/benchmarks/charts-v2-baseline.md`.

### Phase 1 — Determinism and classifier hardening (small, immediate win)

Flag: none (safe fixes).
Files: `app/llm/base.py`, `app/llm/openai_provider.py`, `app/llm/routed.py`,
`app/llm/catalog.py`, `app/insights/resolve.py`, `app/doctables/text_adapter.py`.

Tasks
1. Add `temperature: float | None = None` and `json_mode: bool = False` to
   `LLMProvider.generate` (interface + every impl + fakes). OpenAI-compatible
   impl passes `temperature` and `response_format={"type":"json_object"}` when
   `json_mode` and the catalog marks the model as supporting it; otherwise the
   extractor regex still applies.
2. Chart classifier and text extractor call with `temperature=0`,
   `json_mode=True`. Classifier `MAX_TOKENS` → 600 (the JSON grows in Phase 4).
3. **One chart model per org**: Chart mode resolves with the org's configured
   chart model (`ModelChoice.charts`), not the per-user Ask picker. The picker
   still chooses the caption model, if any. Document this in `CLAUDE.md`.
4. A truncated or unparseable reply is retried **once** (same prompt) before a
   refusal; a 429 surfaces as "Charts are busy, try again in a minute" (not a
   "can't chart" message).
5. Remove the "(sales, budget, revenue, headcount)" bias sentence from
   `_prompt` (R2).

Tests: extend `tests/test_insights_resolve.py` (temperature/json_mode passed;
retry once on truncated JSON; 429 message). Eval: determinism ≥ 95%.

### Phase 2 — Dataset layer v2: profiling, periods, units, hashes, multi-measure SQL

Flag: `CHARTS_V2_DATASETS` (reads; writes always on once merged).
Files: `app/doctables/extract.py`, new `app/doctables/periods.py`,
`app/doctables/store.py`, `app/doctables/table_adapter.py`,
`app/insights/tables.py`, `app/agent/insights_agent.py`.

Tasks
1. **Period parser** `periods.py` (format parsing, allowed by CLAUDE.md):
   `parse_period(text, fiscal_start_month) -> (start, end, grain) | None` for
   ISO dates, month names (any common format), `Q1`, `Q1 2026`, `Q1 FY26`,
   `FY26`, `FY 2025-26`, `FY2025/26`, `H1 2026`, `H2 FY26`, `2026`. A bare `Q1`
   inherits the year from the table name/heading or document title if exactly
   one year/FY is written there; otherwise stays unparsed (never guessed).
2. **Profile v2** in `extract.profile`:
   - A column is `period` when ≥ 80% of non-empty cells parse as periods
     (replaces "date" for quarters/halves/FY; true dates stay `date`, which is
     a period of grain day).
   - Per-cell unit stored in `doc_table_rows.units`; a column's unit is the
     common unit, or `mixed`.
   - `shape = wide` when ≥ 2 number columns share one unit and the header
     names are categories of one kind (detected structurally: the first column
     is the only non-number column and every other column is a number).
     Wide tables expose a **virtual series dimension** whose values are those
     headers (named from the table, e.g. "Series"), so "by plan" works without
     an unpivot copy.
   - `content_hash = sha256(normalized header + rows)`.
3. **Query v2** `store.run_table_query`:
   - `values: list[str]` (1–4 number column keys) → one series per value
     column; a wide table's virtual series = all its number columns.
   - Period axis: group by `date_trunc(period, period_start)` or by the row's
     own `period_grain` when coarser than requested (a quarterly table is never
     split into months).
   - `period_range: (start, end)` filter on `period_start/period_end`.
   - Filters accept `IN` lists (`= ANY(%(f)s)`), still bound.
   - **Units guard:** summing rows whose units differ raises `MixedUnits`
     (refused with the units named) — fixes the "150 total" class of bug.
   - Empty cell is absent, never zero (unchanged).
4. Activity metrics: allow 1–4 measures in the same payload shape (two
   activity metrics over the same period, e.g. PRs opened vs merged).
5. Re-profile job: bounded batch per tick re-profiles old tables
   (`doc_tables.extracted_at < profile_v2_release`), no source fetch needed
   (rows are stored).

Tests: `tests/test_doctables_periods.py` (table-driven, incl. fiscal April
start, ambiguous `Q1` with/without a year in the title), extend
`tests/test_doctables.py` (wide detection, units per cell, hash stability,
multi-value SQL, mixed-units refusal, period range), `tests/test_charts_wide_files.py`
must still pass.
Exit gate: all existing chart tests green; eval unchanged or better.

### Phase 3 — Candidate discovery with a relevance floor and dedup

Flag: `CHARTS_V2_CANDIDATES`.
Files: `app/doctables/cards.py` (new), `app/ingestion/pipeline.py`,
`app/agent/routing.py`, `app/insights/tables.py`, `app/doctables/store.py`.

Tasks
1. **Table cards.** For every stored table write one chunk (kind
   `table_card`) on the table's document: document title, table name,
   columns with types/units, period coverage ("Q1 FY26 – Q4 FY26"), up to 10
   category values, row count. Embedded with the normal embedder, stored in
   `chunks` with the document's `org_id`/`workspace_id`/ACL, so the
   visibility predicate applies unchanged. (Check `tests/test_table_chunking.py`
   first: if a card already exists, extend it rather than adding a second.)
   Cards are excluded from Ask retrieval answers (they are not prose) unless
   Ask already uses them today.
2. **Candidate search** `routing._chart_candidates(question, viewer, scope)`:
   hybrid (cosine + any-word keyword, RRF) over table cards only, viewer
   predicate in the same `WHERE` as `org_id`, then:
   - keep a candidate when its cosine ≥ `CHARTS_CANDIDATE_MIN_COSINE`
     (calibrate in Phase 0's eval; start 0.30) **or** its keyword rank is in
     the top 3 **or** its document/table title is named in the question
     (`title_mentioned`, unchanged);
   - **dedup** by `content_hash` (keep the named source, else newest
     `source_last_modified`; remember the others for the caption);
   - cap at `MAX_OFFERED` (6).
   - Zero candidates is a valid result.
3. **Named source**: when the question names a connector ("in Drive", "from

   says "No table in Drive matched; the closest is in Notion: …".
4. Remove the "list every offered table" refusal (R7); refusals now name only
   what was actually relevant or say nothing was.

### Phase 4 — Resolver v2: requested measures, bindings, coverage, shapes

Flag: `CHARTS_V2_RESOLVER`.
Files: `app/insights/resolve.py` (split: new `app/insights/spec.py` for
`ChartSpecV2` + (de)serialisation, new `app/insights/coverage.py`),
`app/insights/tables.py`, `app/insights/query.py`, `app/agent/routing.py`,
`app/api/chat.py`, `app/api/slack_events.py`.

**Model reply schema (JSON, temperature 0):**
```json
{
  "intent": "chart | text_question",
  "requested": [
    {"words": "<asker's exact words for this measure>",
     "bind": {"table": "T1", "column": "<header>"} | {"metric": "<key>"} | null}
  ],
  "group_by": {"words": "...", "column": "<header or dim>"} | null,
  "split_by": {"words": "...", "column": "<header or dim>"} | null,
  "filters": [{"column": "<header or dim>", "values": ["..."], "words": "..."}],
  "range": {"words": "<exact words>", "text": "FY 2025-26"} | null,
  "period": "day|week|month|quarter|half|year",
  "shape": "auto|line|area|bar|grouped_bar|stacked_bar|horizontal_bar|pie|donut|combo|scatter|table",
  "shape_words": "<exact words that asked for the shape, or null>",
  "source_words": "<exact words naming a connector/page, or null>",
  "document": "<page/file they named, copied exactly, or null>"
}
```

**Code verification (`coverage.py`) — every rule refuses, never repairs:**
1. Every `words` quote must be in the squashed question (existing `_squashed`).
2. `requested` must be non-empty for `intent=chart`. Each `bind` must reference
   an offered handle/column or an offered metric.
3. **Binding evidence** for each requested measure, any one of:
   - a format-level match: every alphanumeric token of the column header (unit
     bracket removed) appears in the quote, or vice versa;
   - `similarity(words, "<header> (<table name>)") ≥ CHARTS_BIND_MIN` using the
     configured embedder (calibrate in Phase 0; start 0.60), computed once per
     request, cached;
   - for a long table, the quote matches a **value** of its measure-name column
     the same way (then the binding becomes value column + filter on that
     category).
   No evidence → the measure is **unbound**.
4. Outcome:
   - all bound → chart;
   - some bound → chart the bound ones; the caption and payload `missing`
     say "Not found in your data: operating expenses" (never silent);
   - none bound → **fallback chain** (Phase 6), then `not_available`.
5. Period: `range.text` parsed by `periods.parse_period` with the org fiscal
   start; for activity it becomes `days`/window; for tables a `period_range`.
   A range that matches no rows → "No rows in FY 2025–26; the table covers
   Q1 FY24 – Q4 FY25."
6. Shape is validated against the data, not just allowed lists:
   - `stacked_bar` needs ≥ 2 series of the same unit;
   - `combo` (dual axis) needs exactly 2 units across the measures (bar for the
     first, line for the second; right axis for the second unit); > 2 units →
     refuse with the units named; asked dual axis with one unit → grouped bar
     with a note;
   - `pie/donut` needs one measure and a category breakdown, no negatives;
   - `line/area` needs a period axis with ≥ `MIN_TREND_BUCKETS` (existing
     step-down rule).
   - `shape=auto` → code chooses: period axis → line (1–2 measures) or
     grouped bar (≤ 6 periods); categories → bar (horizontal if > 8);
     two units → combo.
7. Prompt-injection hardening unchanged: question fenced with
   `UNTRUSTED_POLICY`/`UNTRUSTED_REMINDER`; table names/headers/values shown in
   the catalogue are outside text too — fence the catalogue as well and scrub it.
8. **Spec cache**: after verification, store the spec in `chart_spec_cache`
   keyed on (normalized question, sorted candidate ids + `extracted_at`, model,
   prompt version). A hit skips the model call.
9. **Never fall back to an unrelated activity metric or table.** Delete
   `_chart_the_named_table`'s "single column of that type" guess unless the
   requested-measure binding holds.

Payload additions (see §7): `measures[]`, `missing[]`, `range`, `axes[]`,
`sources[]`.

Tests: `tests/test_insights_coverage.py` (each rule; the four production
questions with fixture tables; a model reply binding "revenue" to "Count" is
refused; partial binding names the missing measure; quote not in question
refused; dual axis 2 units ok / 3 units refused; stacked with mixed units
refused), update `tests/test_insights_resolve.py`,
`tests/test_charts_end_to_end.py`.
Exit gate: eval wrong-data charts = 0; correct chart ≥ 85%; not-available ≥ 90%.

### Phase 5 — Extraction v2: facts from prose, state machine, every file type

Flag: `CHARTS_V2_EXTRACTION` (+ existing `DOCTABLES_TEXT_ENABLED`).
Files: `app/doctables/text_adapter.py`, `app/doctables/queue.py` (rename
concept to runs; keep module), `app/doctables/uploads.py`,
`app/ingestion/pipeline.py`, `app/sources/google_drive.py`,
`app/attachments/extract.py`, `app/jobs/worker.py`.

**5a. Facts from prose (TextAdapter v2)**
- Prompt asks for FACTS, not tables:
  `{"facts": [{"measure": "...", "measure_text": "...", "series": "...|null",
  "series_text": "...|null", "period_text": "...|null", "value_text": "₹15L",
  "clause": "...", "context": "...|null"}]}`.
- Code keeps a fact only when ALL hold:
  1. `clause` is verbatim in the document (normalized whitespace/case), 6–300
     chars;
  2. the clause contains **exactly one** value number once the numbers inside
     `period_text` are removed ("Q2 2026" is not a value);
  3. `value_text` is verbatim in the clause, parses (`extract.parse_number`) and
     its unit is the stored unit;
  4. `measure_text`, `series_text`, `period_text` are each verbatim in the
     clause **or** in `context`, and `context` is verbatim in the document and
     ends ≤ 400 chars before the clause (a heading or the lead-in of a list);
  5. `measure` (canonical name) is either `measure_text` or embedding-close to
     it (≥ `CHARTS_BIND_MIN`); otherwise `measure = measure_text`;
  6. `period_text` parses with the org fiscal start, or is stored unparsed;
  7. two facts with the same (measure, series, period) and different values →
     both dropped, recorded in the run's `error` as a conflict count.
- Stored as ONE long table per document: `Measure | Series | Period | Value`
  with per-cell units, `period_start/end`, `quote = clause`, `context`.
  Charts filter by Measure, split by Series, axis by Period. Title suffix
  "(taken from text)" stays.
- Long documents: read in windows of `text_max_chars` (default 12k) up to
  `CHARTS_TEXT_MAX_TOTAL_CHARS` (default 60k) — one call per window; beyond the
  cap the run is `partial` and the chart says how much was read.
- Run on **every** indexed document type that passes `wants` (Notion, Drive,
  Linear issue bodies, Slack threads); Slack threads only when the thread has
  ≥ `MIN_NUMBERS` numbers (cost bound).

**5b. State machine (`doc_adapter_runs`)**
- `enqueue` = upsert (document, origin) with the new `content_hash`; if the
  hash is unchanged and status is `done|empty`, do nothing.
- `claim` sets `status='running'`, a fresh `claim_token`; `finish(token, ...)`
  updates **only if the token matches** (fixes the overwrite race).
- Outcomes: tables found → `done` (+ replace tables of that origin);
  nothing found (valid JSON, zero kept facts) → `empty` and **delete that
  origin's tables**; unparseable/truncated reply → retry (counts an attempt)
  → `failed` after `text_max_attempts`; window cap hit → `partial`; adapter
  disabled → `skipped` (re-queued automatically when it is enabled).
- Each document/attachment is processed in its own transaction; one failure
  never aborts the batch (fixes the FK abort).
- `tables_checked_at` is retired: backfill now enqueues every (document,
  origin) with no run row for an **enabled** adapter, bounded by
  `DOCTABLES_BACKFILL_BATCH` per tick (move it from per-sync to the tick so
  idle orgs catch up). The 12 unchecked production Drive documents get read.
- `GET /insights/extraction-status` (admin): counts by status per connector,
  for the Sources page ("Figures read: 31 done · 2 reading · 1 failed").

**5c. On-demand extraction in Chart mode**
- When a candidate document (from Phase 3 search over **document chunks**, not
  cards) is relevant (cosine ≥ floor) but its `text` run is `pending|skipped`
  or absent, run the TextAdapter **now** on at most `CHARTS_ONDEMAND_DOCS`
  (default 2) documents, as an interactive call (never throttled), with a
  20 s budget, then re-run candidate search. Emit an SSE `status` event
  ("Reading figures from 'Q3 Board Update'…").
- If it is `running` in the background, wait up to 10 s, then answer
  "Figures in 'X' are still being read — ask again in a minute" (never a
  generic refusal).

**5d. File types at ingest (parity with uploads)**
- Move the upload readers (`_pdf_tables`, `_xlsx_tables`, `_docx_tables`,
  `_csv_tables`) into `app/doctables/extract.py` (one reader per format, used
  by both uploads and ingestion).
- Drive: PDF → pdfplumber tables + pypdf text (text stays for chunks);
  `.xlsx` → all sheets; Google Sheets → export as XLSX (all tabs, existing
  `drive.readonly` scope) instead of CSV-first-tab; DOCX → Word tables (already
  rendered) — verify in tests.
- Notion: unchanged (pipe tables + inline databases).
- Bounded: `MAX_TABLES_PER_DOCUMENT`, `MAX_ROWS`, PDF pages
  (`DOCTABLES_PDF_MAX_PAGES`), truncation marked.

Tests: `tests/test_doctables_text.py` (the ₹12L/₹15L mis-association is
dropped; one-figure clause; context window; unit mismatch dropped; conflicts
dropped; windows + partial), `tests/test_doctables_runs.py` (token race,
empty clears tables, unparseable retries then fails, skipped → re-queued on
enable, per-doc transaction), `tests/test_drive_tables.py` (PDF, XLSX, all
Sheet tabs; fake Drive rejects unknown URLs), `tests/test_doctables_uploads.py`
still green.
Exit gate: eval correct-chart ≥ 90% including prose-only fixtures.
